## Architecture notes

- **Calendar stack:** CalendarView (UI) → calendarModel (month grid, keys) → useDailyNoteDates →
  `notes.getDailyDates` (shared notes service) → the notes database. Opening a date:
  `resolveDailyNoteId` (date index → title search → create) → `openDailyNoteInCurrentTab`.
- **Day definition:** the daily-note day (it begins at sunrise — `dailyNoteToday`), the same one the
  titles use; the calendar never defines its own.
- **Overlay vs tab:** the overlay is a sheet — contextual, no history, no state; the Calendar tab is
  tab state (month, selected) and history like any tab.
- **History of a type change to a note:** the change's own step now IS the note (store
  `typeChangeEntryFor` records `noteId`, not a `home` list step) and nothing records it twice, so
  ‹ from a calendar day lands exactly on the previous tab.
