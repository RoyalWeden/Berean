# Mac reader return diagnosis

The isolated Mac QA Genesis 1 KJVA reader returned from other tabs or a relaunch with different scrollbar fractions. The baseline was `.07135575942915393`. Observed return values include `.07198247535596912`, `.07675438596491228`, and `.0712719298245614`. The fixture had verse 1 selected, the Notes inspector open, and Strong’s off. Manually restoring the original fraction recovered the fixture. The underlying point offsets and legal scroll ranges were not captured in these reproductions. [Current state](CURRENT-STATE.md) · [Relaunch observations](COMPARE-DURABLE-2026-11-23.md)

## Source evidence at `f0d03d6d`

- The Mac reader captures a point offset as `max(0, clip.bounds.minY - clip.documentRect.minY)`, along with a semantic verse and the selection. ScriptureView caches it and persists the typed record in `nativeReaderPositions`, keyed by chapter edition within each tab. The Mac capture supplies neither width nor within-verse offset. Same-layout return adds the saved points to the current document origin and constrains the result against the current clip. The zero-offset verse fallback and chapter-end intent are separate branches. [Mac capture](../../apple/BereanMac/ChapterTextView.swift#L998-L1010) · [Cache and persistence](../../apple/Shared/ScriptureView.swift#L294-L337) · [Restore](../../apple/BereanMac/ChapterTextView.swift#L451-L489)
- The pending action waits for an attached, positive-size viewport and retries when clip size, document frame, or text inset change. It remains pending through a 0.5-second layout quiet period. The idle checkpoint and dismantle skip capture while the restore owns the viewport. The key still omits the scroll view content insets and its legal scroll range. [Geometry and layout](../../apple/BereanMac/ChapterTextView.swift#L27-L76) · [Idle checkpoint](../../apple/BereanMac/ChapterTextView.swift#L115-L125) · [Dismantle](../../apple/BereanMac/ChapterTextView.swift#L339-L346)
- Prior trace for commit `852a4767` showed a correctly applied 446-point Back/Forward restore later moving to 440 points with unchanged tracked geometry. The existing next-main-turn correction is bounded and scoped to the pending action. Current code enables it only for `firstPassage && restore != nil`, where `restore` is the history request. Ordinary tab return and cold launch can both load a saved position while that history request is absent. [Prior trace summary](CHECKPOINT-HISTORY-2026-11-21.md#L43) · [Correction gate](../../apple/BereanMac/ChapterTextView.swift#L451-L461) · [Correction](../../apple/BereanMac/ChapterTextView.swift#L94-L113)
- A resize gathers previously visible selected ranges, resizes the view, reapplies a pending viewport action, then tries to reveal one of those ranges. That reveal can move the clip after the restore. The usual selection-change reveal requires a newly added selection on the same passage. A matching saved selection suppresses an explicit jump at mount, while a selection mismatch or explicit navigation can set a target. Trace which action ran before changing selection handling. [Resize](../../apple/BereanMac/ChapterTextView.swift#L170-L177) · [Selection reveal](../../apple/BereanMac/ChapterTextView.swift#L376-L378) · [Reveal dispatch](../../apple/BereanMac/ChapterTextView.swift#L439-L449) · [Target precedence](../../apple/Shared/ScriptureView.swift#L650-L662)
- The Notes inspector can change reader width during attachment. Title-bar clearance feeds the TextKit inset and the floating selection bar feeds bottom scroll clearance. A different fraction can therefore accompany the same point offset. Earlier QA recorded an unchanged 446-point offset with a one-point change in scrollable extent. The present fractions are also consistent with multiple geometries. For example, 70/981 and 70/912 match two of the reported fractions. Those ratios illustrate the ambiguity and are not measurements of this fixture. ## Isolated QA capture

Use only the owned Mac QA profile. At the original inspector width, select Genesis 1:1 and scroll to a partial line below it so the selected verse is above the viewport. Leave the divider, window, and controls in place. Record the original settled position after the idle checkpoint. Repeat Notes → reader and Compare → reader three times each, then cold reopen and run one Back/Forward cycle. Preserve a separate trace for a return immediately followed by wheel or scrollbar input.

If temporary native logging is needed, keep it QA-only and bounded to these transitions. Record no passage text or user content. For each return, log the loaded saved offset and selection match, requested and actual origin before and after clamp, clip bounds and document rect, constrained minimum and maximum origins, NSTextView frame and text inset, NSScrollView content insets, native scroller fraction, and first visible verse/line crop. Record those values at outgoing capture, restore application and reapplication, any selection reveal, native scroll reflection when geometry or origin changes, and the settled checkpoint. Tag events with the current action and reason so post-restore movement can be attributed. Remove temporary logging before shipping.

| Observation | Fix gate |
| --- | --- |
| Same origin and visible line/crop, changed legal range | The fraction changed with the extent. Identify the layout difference before proposing a reader offset change. |
| Correct origin after restore, then moved origin at unchanged geometry during restoration | Extend the existing bounded AppKit correction to first-mounted ordinary saved positions. Keep its input cancellation and navigation guards. |
| A resize selection reveal changes the origin after the restore | Give a pending saved restore precedence over resize-driven reveal until it settles or the user takes control. Preserve direct selection reveal and explicit jumps. |
| Origin was wrong at application, or the stored offset changed before the restore | Trace legal clamping, outgoing capture and selection-target precedence. Fix the responsible path before expanding correction. |
| Geometry remains meaningfully different after settling | Evaluate the visible line and crop separately. A same-layout point-offset test does not establish reflow behavior. |

For a same-geometry pass, require the same visible line/crop and point offset within one physical pixel, with the settled saved offset matching. Also check that immediate user input wins and its new position survives a return, an explicit picker/Go request reaches its verse, and selection near the last verse still gets clearance above the floating controls. No source change or new runtime result is recorded here.
