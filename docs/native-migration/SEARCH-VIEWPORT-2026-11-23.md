## Storage and restoration

- The Search tab stores a device-local record under `filters.$nativeSearchViewports`. It keeps up to 16 recent rendered contexts in `positions` and one separate `active` visit with configuration, optional context and row, and optional centered alignment. Manual scroll uses top alignment. A rowless active visit represents the start and suppresses fallback to another visit’s bookmark. The legacy filter siblings and existing scroll/result fields are preserved. Malformed legacy filter containers are left intact. Database schema and sync fields stay unchanged.
- The configuration fingerprint covers query, edition scope, word mode, book/testament filters, tag settings, focused text, sort and grouping. The rendered-context fingerprint includes that configuration, effective texts/books/mode/tag membership, result context, default text and applicable replacer rules. It hashes canonical structured JSON. Anchors are stable edition/book/chapter/verse IDs or actual group IDs and must exist in the loaded results before use.
- Opening a result records a centered return target before navigation. Back and Forward stage their specific visit independently of the most recent destination and trigger restoration with a tab-scoped revision. Restoration and capture validate the active Search tab, configuration and revision. Real user scrolling updates the visible-row bookmark. Geometry and gesture-end capture distinguish the physical top edge from the first visible row, including when the row ID itself does not change.
