## Delivered behavior

- Observable main-actor WorkspaceStore owns canonical sessions, display orders, archives and committed order keys. AppModel forwards existing access/writeback; nested SwiftUI observations still work. No independent DB, service, lock or stale full snapshot per window was added.
- SessionsService.applySnapshot accepts optional device-local active-tab state and commits it with upserts/tombstones/archives in one transaction and timestamp. Existing callers/default API and serializers remain compatible. Change events follow successful commit only. Keys and currentSessionId advance only after success; failed saves retain the live edits for retry.
- Bootstrap does not enable the writer until every persisted workspace/local-state row has loaded. A failed read cannot save the seeded fallback over real tab rows. This is specifically a workspace safeguard, not globally read-only recovery: existing content services/defaults may still write.
- Mac's application delegate, retained beyond view teardown, flushes workspace state on Quit. An actual failed save cancels Quit and leaves the existing Library alert/live workspace available for retry. This is not a confirmation for successful Quit. iPhone attempts the workspace flush at app-level scene background for all tab types and empty content. Suspension cannot be vetoed. Failed iPhone saves still lack visible libraryError UI/foreground retry; that is the next priority, not completed recovery.
- Debug Mac QA can combine --qa-library and --qa-slow-workspace-save to delay the debounce10sec. Normal400ms behavior and user settings are unchanged. Do not use the test flag for owner builds/normal launch. No schema, sync allowlist, canonical ID, signing or production-data change.
